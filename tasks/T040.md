# T040: Display widths (wide, combining and zero-width clusters)

Phase 4 · Model: sonnet: one pure level-1 placement rule (R18) with exact table tests · Depends-on: T038

## Brief
Package `internal/tui` (module `github.com/0x6c6d/fastread`). Existing (keep):
```go
type Cell struct { Text string; Style Style; Cont bool } // Text "" = blank cell
type Frame struct { W, H int; Cells [][]Cell; Size int } // Cells[y][x]; Size = level drawn
func Render(m Model, w, h int) Frame // Model{Word, Size, Paused, ShowProgress, ShowHelp, Index, Total, WPM, EffectiveWPM}
func EffectiveSize(word string, size, w, h int) int
```
A word with any grapheme cluster that is not a single Latin-1 rune renders at level 1 (one
row, row h/2) whatever its size. Level 1 today: clusters `cs := orp.Clusters(word)`, focus
`fi := orp.Index(word)`, the focus cluster starts at column w/2, the others are placed left
and right of it by `uniseg.StringWidth` (github.com/rivo/uniseg v0.4.7).

Make the level-1 placement exact for R18:
1. Cell width of a cluster c: `uniseg.StringWidth(c)` (2 for wide/emoji, combining marks
   stay inside their cluster). A cluster of width 0 (a lone combining mark, U+200B, a
   control rune) is NOT skipped: it occupies one cell whose Text is `"◌" + c` (U+25CC), so
   every cluster is visible and the focus always has a cell.
2. Cluster k > fi starts at w/2 + Σ width(cs[fi..k−1]); k < fi starts at
   w/2 − Σ width(cs[k..fi−1]) (left-padded, never re-centred).
3. A 2-wide cluster: Text in its left cell, the right cell is `Cont: true`, `Text ""`,
   `StylePlain` (only the left cell of a focus cluster is `StyleFocus`, so the focus column
   of a wide focus cluster is its left cell). A cluster that does not fit completely inside
   [0, w) is not drawn at all (never half a wide cluster, never a `Cont` cell at column 0
   or without its left cell).

Tests, `internal/tui/widths_test.go`, table-driven, sizes 1–5 × widths 80 and 121 × height
24 (every frame must have `Size == 1`). Words, with the expected focus cluster:
`日本語の本`→`本`, `한국어`→`국`, `👍👍👍`→middle `👍`, `ok👍`→`k`, `e\u0301te\u0301`→`t`,
`cafe\u0301`→`a`, `\u0301abc`→`b`, `a\u200bb`→`b`, `🇩🇪🇫🇷`→`🇩🇪`, `👩‍👩‍👧x`→`x`,
`\u0301`→`◌\u0301`, `日本`→`本`, `Ωmega`→`m`.
- `TestWideAndCombining`: exactly one `StyleFocus` cell, at (w/2, h/2), Text = expected
  focus (= `orp.Clusters(w)[orp.Index(w)]`, prefixed with `◌` when its width is 0); if the
  focus is 2 wide, cell (w/2+1, h/2) is `Cont`, `StylePlain`, `Text ""`. Reading row h/2
  left to right over non-`Cont`, non-blank cells and dropping the `◌` prefix of width-0
  cells gives back the word. The occupied cells (non-blank or `Cont`) are contiguous and
  number Σ max(1, width) over the clusters. Spot checks at 80: `ok👍` has `o` at 39, `k` at
  40, `👍` at 41 and `Cont` at 42; `👩‍👩‍👧x` has the family at 38 and `Cont` at 39;
  `\u0301abc` has `◌\u0301` at 38.
  Clip rows: `a日日日日日日日日日日日日日日` and `日日日日日日日日日日日日日x` at widths 20 and 21
  (any part on screen): no `Cont` cell at column 0, every `Cont` cell has a non-blank
  2-wide cell directly left of it, no 2-wide cluster in the last column, focus at w/2.

Constraints: change only `internal/tui/render.go` and create `internal/tui/widths_test.go`;
earlier internal/tui tests must keep passing unchanged; pure, no I/O.
