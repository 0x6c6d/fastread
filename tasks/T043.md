# T043: Encode hardening (control stripping) and colour modes on full frames

Phase 4 · Model: opus: last line of defence against terminal-escape injection from untrusted text (§5 security, Risk "Terminal escape injection") · Depends-on: T027, T041, T042

## Brief
Package `internal/tui` (module `github.com/0x6c6d/fastread`). Existing (keep):
```go
type ColorMode int // ColorNone (NO_COLOR), Color16, Color256, ColorTrue, in this order
func DetectColorMode(getenv func(string) string) ColorMode
type Style uint8   // StylePlain, StyleFocus, StyleTick
type Cell struct { Text string; Style Style; Cont bool } // Text "" = blank
type Frame struct { W, H int; Cells [][]Cell; Size, Parts int }
func Render(m Model, w, h int) Frame // Model{Word, Size, Paused, ShowProgress, ShowHelp, Index, Total, WPM, EffectiveWPM, Part}
func Encode(f Frame, mode ColorMode) []byte
```
`Encode` today: per row y `"\x1b[<y+1>;1H"`, then the cells (blank → `' '`, `Cont` →
nothing), switching SGR only when the style changes (reset `\x1b[0m` before each switch),
`\x1b[0m` at the end of each row. SGR: plain ColorTrue `\x1b[38;2;255;255;255m`, Color256
`\x1b[38;5;231m`, Color16 `\x1b[97m`, ColorNone none; focus `\x1b[38;2;255;0;0m`,
`\x1b[38;5;196m`, `\x1b[91m`, ColorNone `\x1b[1;7m`. At sizes 2–5 the whole focus glyph box
(blank cells too) is `StyleFocus`; ticks `│` are `StyleTick`.

Change `encode.go` (and `color.go` only if needed):
1. `StyleTick` has no colour in every mode: reset only, the terminal's default foreground.
2. Defence in depth (§5): `func cleanCell(s string) string` (unexported, own
   implementation; do not call `internal/tokenize` from non-test code): each invalid UTF-8
   byte → U+FFFD; remove C0 U+0000–U+001F, DEL U+007F, C1 U+0080–U+009F, U+202A–U+202E,
   U+2066–U+2069; keep everything else. No allocation when nothing changes. Encode writes
   `cleanCell(text)` for every non-`Cont` cell and `' '` when that is empty (columns stay
   aligned). A raw `0x9B` byte must never reach the output.
3. Malformed frames never panic: write at most `min(f.H, len(f.Cells))` rows and at most
   `min(f.W, len(row))` cells per row; W or H ≤ 0 → empty output.
4. The output consists only of CUP `\x1b[<n>;1H`, the SGRs above, `\x1b[0m` and cleaned
   cell text.

Tests, new `internal/tui/encode_test.go`, table-driven; helper `stripCSI` removes every
match of `\x1b\[[0-9;]*[Hm]`; "leak-free" = valid UTF-8 and, after `stripCSI`, no rune in
U+0000–U+001F, U+007F–U+009F, U+202A–U+202E, U+2066–U+2069:
- `TestEncodeStripsControls`: (a) a hand-made 4×1 frame `"a\x1bb"`, `"\x07"`, `"c"`, `"\x9b"`
  → `stripCSI(Encode(f, m))` is exactly `"ab c\ufffd"` for every mode; (b) cells
  `"\x1b[2J"`, `"\x1b]0;pwned\x07"`, `"\u009b31m"`, `"\xff\xfe"`, `"a\x00b"`, `"\u202eevil"`,
  `"\u2066x\u2069"`, `"\x7f"`, `"\r\n"`, `"é"`, `"👍"` (+`Cont`) in all modes: leak-free,
  `[2J`, `]0;pwned`, `evil` visible; (c) `Render` of the word
  `"a\x1b[31mb\x9bc\u202ed\x07e\x00f\xffg\x1b]0;x\x07"` at sizes 1 and 3 with both toggles,
  every mode: leak-free; (d) for every rune 0..0x10FFFF except surrogates and for the
  strings above: `cleanCell(s) == tokenize.Sanitize(s)` (test-only import); (e) malformed
  frames (`Cells` nil with W 5 H 3, rows shorter and longer than W, W −1, H −1): no panic,
  at most W runes per row after `stripCSI`.
- `FuzzRenderEncode(f *testing.F)` with args `(word string, size, w, h, mode uint8)`; seeds
  include the hostile strings above; body: `Render(Model{Word: word, Size: int(size)%7,
  ShowProgress: true, ShowHelp: true, Total: 1}, int(w)%161, int(h)%61)` has the requested
  dimensions, and `Encode(f, ColorMode(mode%4))` is leak-free.
- `TestColorModes` (AC11, R14): getenv maps `COLORTERM=truecolor`, `COLORTERM=24bit` →
  ColorTrue; `TERM=xterm-256color`, `TERM=screen-256color` → Color256; `TERM=xterm`, empty →
  Color16. For `Render(Model{Word: "Hello", Size: 1, ShowProgress: true, ShowHelp: true,
  Total: 3}, 80, 24)`: the mode's focus SGR occurs exactly once, immediately followed by `e`
  and then `\x1b[0m`; no other mode's focus SGR occurs; the mode's plain SGR occurs; no
  background SGR (no `48;` and no match of `\x1b\[(?:[0-9]+;)*(?:4[0-9]|10[0-7])(?:;[0-9]+)*m`);
  each of the two `│` is immediately preceded by `\x1b[0m`. At Size 3 the focus SGR occurs
  exactly 5 times, each followed by exactly 6 runes from `' ' '▀' '▄' '█'`, then `\x1b[0m`.
- `TestNoColor` (R14): `NO_COLOR=1` (also `yes`) with `COLORTERM=truecolor`,
  `TERM=xterm-256color` → ColorNone; `NO_COLOR=""` with `TERM=xterm-256color` → Color256.
  ColorNone output (sizes 1 and 3, both toggles): no `\x1b[38`, no match of
  `\x1b\[(?:[0-9]+;)*(?:3[0-9]|9[0-7])(?:;[0-9]+)*m`, the only SGRs are `\x1b[0m` and
  `\x1b[1;7m`; size 1: `\x1b[1;7m` exactly once, followed by `e`; size 3: exactly 5 times,
  each followed by the 6 runes of the focus box.

Constraints: change only `internal/tui/encode.go` (and `color.go` if needed), create
`internal/tui/encode_test.go`; `TestEncodeColors`, `TestDetectColorMode` and all render tests
keep passing unchanged; must pass with `-race`.

## Verification
`scripts/verify/T043.sh` exits 0. It runs the check command, the three tests and the
earlier colour/render tests (also with `-race`), fuzzes `FuzzRenderEncode` for 15 s, and
runs its own hostile-text program against `Render`+`Encode` in every mode. Negative checks:
the fuzzer finds no leak, the independent program finds no control byte (and its detector
is proven to fire on a raw ESC), `encode.go` does not delegate to `internal/tokenize`.
