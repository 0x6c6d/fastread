# T048: TUI loop on Player deadlines (keys, split steps, drift)

Phase 5 · Model: opus: the event loop's timers, key handling and absolute-deadline timing are concurrency and timing-accuracy critical (R26, R20 timing, §5 timing accuracy; Risk "flaky timing tests") · Depends-on: T041, T042, T046, T047

## Brief
Package `internal/tui` (module `github.com/0x6c6d/fastread`). Today `Run` (in `run.go`)
only knows quit keys and calls `Tick` on a timer. Make it the full loop. Existing (keep
names, signatures and behaviour): `Run(ctx context.Context, t Terminal, p *state.Player,
opts Options) (last int, err error)`, `Options{Getenv}`, `Terminal`, `EnterSeq`,
`RestoreSeq`, `OpenTTY`; MakeRaw → EnterSeq → one deferred cleanup on every path incl.
panics (RestoreSeq, `Restore`, `Close`, wait for the reader goroutine; a panic becomes the
error `tui: internal error: <value>`); the reader goroutine; colour mode detected once.
Also existing: `Render(Model, w, h) Frame`, `Encode(Frame, ColorMode) []byte`,
`EffectiveSize(word string, size, w, h int) int` (0 = too small), `Split(word string,
size, w int) []string`, `Model{Word, Size, Paused, ShowProgress, ShowHelp, Index, Total,
WPM, EffectiveWPM, Part}` (EffectiveWPM 0 = unknown), `Frame{W, H, Cells, Size, Parts}`;
`KeyDecoder` (`Feed`, `Pending`, `Flush`) and `EscTimeout`; Player: `Start Tick Apply
Deadline Index Len Token Playing Finished WPM Size ShowProgress ShowHelp EffectiveWPM
SetParts Part Parts` (`SetParts` keeps time already spent in the current step; equal parts
are a no-op).

Move `Run` and its loop into new `internal/tui/loop.go` (`run.go` may keep `Options` or be
deleted). Add unexported package-level seams, used only by tests: `renderFn = Render`,
`encodeFn = Encode`, `frameHook func(m Model, f Frame)` (nil in production; called from the
loop goroutine right after a frame was written).

Loop rules:
1. Redraw = `w, h := t.Size()` (error → return `p.Index()` and an error wrapping it, with
   the usual cleanup); `s := EffectiveSize(word, p.Size(), w, h)`; `p.SetParts(nil)` when
   s == 0, else `p.SetParts(Split(word, s, w))`; model from p (`Paused: !p.Playing()`,
   `Total: p.Len()`, `EffectiveWPM` = value if ok else 0, `Part: p.Part()`); `renderFn` with
   the same w, h → `encodeFn` → one `t.Write`; then `frameHook`. Word = `p.Token().Text`.
2. Start: `p.Start()`, redraw.
3. One `select` per iteration over: ctx done → return `p.Index(), nil`; key chunk →
   `Feed` → apply actions in order (`ActQuit` → return `p.Index(), nil` at once; others
   `p.Apply`) → one redraw per chunk; Esc timer (armed for `EscTimeout` after a chunk that
   leaves `Pending()` true, stopped otherwise) → `Flush` actions, then as for keys;
   deadline timer, armed only while `p.Playing()` for `time.Until(p.Deadline())` → `p.Tick()`;
   finished → return `p.Index(), nil` (end of text exits right after the last step's delay);
   else redraw. Re-arm both timers after every event; stop them on return. No `time.After`,
   no `time.Sleep`, no goroutine besides the reader.
4. Never `now + delay` scheduling in the loop: the deadline always comes from the Player.

Tests, `internal/tui/loop_test.go` (reuse and, if needed, extend the fake `Terminal` from
`run_test.go` without breaking its tests; record frames through `frameHook`, restore seams
with `t.Cleanup`; every Run bounded by a test timeout; poll with deadlines, no fixed sleeps
except where stated):
- `TestLoopKeys`: tokens `w0`…`w29`, 50 wpm, size 2, 80×24. Feed in order, waiting for the
  frame after each: `" "` → Paused; `"\x1b[C"` → Index 1; `"\x1bOC"` → 2; `"\x1b[D"` → 1;
  `"\x1b[1~"` → 0; `"]"` → Size 3; `"["` → 2; `"\x1b[A"` → WPM 325; `"\x1b[B"` → 300;
  `"p"` → ShowProgress false; `"?"` → ShowHelp true; `" "` → playing, `"\x1b[C"` → Index 10;
  `"\x1b"` then `"[C"` 10 ms later → Index 20, no quit; garbage `"\x00\xffQx\x1b[5~\x1bOP"`
  and `"\x1b[" + 100×"9" + "~"` → nothing changes, still running; then table rows: final
  key `q`, `"\x03"`, lone `"\x1b"` (quits after `EscTimeout`, within 1 s) → Run returns
  (current index, nil) and the output ends with `RestoreSeq`.
- `TestLoopSplitSteps`: tokens `go`, `W := strings.Repeat("abcdefghij", 6)`, `end.`; 1500
  wpm, size 1, terminal 20×24. The frames' (Index, Part) sequence without duplicates is
  (0,0), (1,0)…(1,4), (2,0); for every frame `m.Part < f.Parts` and `p.Parts() == f.Parts`
  (checked inside the hook); the word row of each (1,k) frame reads `Split(W, 1, 20)[k]`;
  the time from the first (1,0) frame to the (2,0) frame is within ±25% of the sum of the
  five step delays (`timing.Delay` of each part without its `-`, last via `DelayPara`).
  A second row at 100 wpm (720 ms per step) pauses (`" "`) as soon as it sees (1,2), waits
  300 ms (fixed sleep allowed), sees Part still 2, resumes (`" "`) and still sees (1,3),
  (1,4), (2,0) in order.
- `TestLoopDriftRealClock` (§5 timing, Plan row 32): 100 tokens cycling `word`, `word,`,
  `word.`, `extraordinarily`, `naïve`, `ParaEnd` on every 10th and the last; 1500 wpm;
  size 1; 80×24; `state.SystemClock{}`; the fake terminal's `Write` sleeps 5 ms per call
  (a loop scheduling `now + delay` would drift by ≥ 500 ms). Elapsed time from calling
  `Run` to its return is within ±5% of Σ `timing.DelayPara` over all tokens; Run returns
  (99, nil) and `p.Finished()`.

Constraints: change only `internal/tui/run.go`, create `internal/tui/loop.go` and
`internal/tui/loop_test.go` (edit `run_test.go` only to extend the fake); all earlier
`internal/tui` and `cmd/fastread` tests keep passing; no `.Fd()`, no `os.Exit`, no Gio, no
signal handling here.

## Verification
`scripts/verify/T048.sh` exits 0. It runs the check command, the three `TestLoop*` tests
and the earlier `TestRun*`/`TestKeyDecode` tests (also `-race -count=2`), the cmd resume
tests, and drives the binary in an isolated tmux. Negative checks: PageUp/F1/`x`/`Q` keep
it running and unchanged, an arrow key never quits, no `time.Sleep`/`time.After` in
`loop.go`, no `.Fd()`/`os.Exit`/Gio in `internal/tui`.
