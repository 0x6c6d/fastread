# T060: Gio key map (TestGUIKeyMap)

Phase 6 · Model: sonnet: a fixed key table over Gio's key types with a table test, no window and no concurrency (R26 for the GUI) · Depends-on: T008, T030

## Brief
Package `internal/gui` (module `github.com/0x6c6d/fastread`; `gioui.org v0.10.3` is pinned,
its source is in `$(go env GOMODCACHE)/gioui.org@v0.10.3`, see `io/key/key.go` and
`io/input/key.go`). From `internal/state`: `Action` constants `ActNone ActTogglePause
ActWPMUp ActWPMDown ActSizeDown ActSizeUp ActPrev ActNext ActHome ActToggleProgress
ActToggleHelp ActQuit`.

How Gio v0.10.3 reports keys on X11 (checked under Xvfb with xdotool): letters arrive
upper-case (`q` → `Name "Q"`, no modifiers; Shift+q → `"Q"` with `ModShift`); `?` → `Name
"?"` with `ModShift`; `[` → `"["`, `]` → `"]"`; Space → `key.NameSpace`; arrows
`key.NameLeftArrow` … `NameDownArrow`; Home `key.NameHome`; Escape `key.NameEscape`; Ctrl+C
→ `"C"` with `ModCtrl`; every key also produces a `Release` event; `Shift`/`Ctrl` themselves
arrive as `Name "Shift"`/`"Ctrl"`. A window receives a key only if a `key.Filter` for it
was registered (a filter matches iff `Name` is equal, `e.Modifiers & Required == Required`
and `e.Modifiers &^ (Required|Optional) == 0`).

Create `internal/gui/keys.go`, first line `//go:build !nogui && cgo`:
```go
// keyFilters returns the filters the window passes to gtx.Event each frame: exactly one
// key.Filter (Focus nil) per row of the table below.
func keyFilters() []event.Filter
// keyAction maps a key event to a player action (R26). ok is false for Release events and
// for every event no filter row matches.
func keyAction(e key.Event) (a state.Action, ok bool)
```
Table (Name, Required, Optional → action): `Space` → ActTogglePause; `↑` → ActWPMUp; `↓`
→ ActWPMDown; `[` → ActSizeDown; `]` → ActSizeUp; `←` → ActPrev; `→` → ActNext; `⇱`
(Home) → ActHome; `"P"` → ActToggleProgress; `"?"` (Optional ModShift) → ActToggleHelp;
`"Q"` → ActQuit; `⎋` (Escape) → ActQuit; `"C"` (Required ModCtrl) → ActQuit. Required and
Optional are 0 unless stated. Use one table (slice of structs) for both functions so they
can never disagree.

Tests in `internal/gui/keys_test.go`, first line `//go:build !nogui && cgo`:
- `TestGUIKeyMap` (R26, AC21 GUI part), table-driven over `key.Event` values (State Press
  unless stated): every table row → its action; `"Q"` with ModShift, `"P"` with ModShift,
  `"C"` without ModCtrl, `"C"` with ModCtrl|ModShift, `"X"`, `⇞` (PageUp), `"F1"`,
  `"Shift"`, `"Ctrl"`, `""`, `"q"` (lower-case) → not ok; every row's Release → not ok;
  Space/arrows with ModCtrl → not ok. Consistency: for each event in the test set,
  `keyAction` is ok iff some filter from `keyFilters()` matches it by the rule above (write
  that matcher in the test); every filter is a `key.Filter` with nil Focus; the 13 rows are
  all distinct; every action except ActNone is reachable.

Constraints: create only `internal/gui/keys.go` and `internal/gui/keys_test.go`; do not
change `window.go` yet (a later task wires the map in); no new dependency; no display, no
window, no `os.Exit`.
