# T035: Resume on the GUI exit path (finish callback)

Phase 3 · Model: opus: the `app.Main`/`finish` exit path is the only place the GUI can persist state and set the exit code (Risk "GUI exit path", Consequential assumption 8, R29) · Depends-on: T034

## Brief
Make the GUI branch of `cmd/fastread` (module `github.com/0x6c6d/fastread`) save and delete
the resume entry exactly like the TUI branch. Existing (keep names/behaviour): in `run.go`
the seams `openTerminal`, `stdinIsTTY`, `exitProcess` (= `os.Exit`), `runTUI`,
`notifyContext`; `runErr`/`run`/`exitCode`; the GUI branch calls
`gui.Run(ctx, p, gui.Options{Getenv: getenv}, finish)` where `finish func(last int, err
error)` prints one `fastread: <msg>` line for a non-nil err and calls `exitProcess(0 or 1)`;
a synchronous error from `gui.Run` (no display, nogui/no-cgo stub) → one line, exit 1. In
`resume.go`: `type resumer`, `newResumer(doc, getenv, stderr) *resumer` (nil for raw/stdin),
`(r *resumer) start(o, n, stderr) int`, `(r *resumer) finish(p *state.Player, last int)
error` (nil-safe; Finished → Delete, else Save; errors wrapped "saving reading position:
%w"). `gui.Run` never returns on success on Linux (it calls `app.Main`) and calls `finish`
exactly once from the window goroutine on quit, window close, end of text, ctx cancel
(SIGINT/SIGTERM) or window error.

Changes in `cmd/fastread/run.go` only:
- New seam `runGUI = gui.Run`; the GUI branch calls `runGUI`.
- The GUI `finish` callback becomes: `ferr := r.finish(p, last)` (always, also when `err` is
  non-nil); if `err != nil` → one line for `err`, `exitProcess(1)`; else if `ferr != nil` →
  one line for `ferr`, `exitProcess(1)`; else `exitProcess(0)`. Exactly one stderr line at
  most, `exitProcess` called exactly once (guard with `sync.Once`).
- A synchronous error from `runGUI` → one line, return 1, nothing saved or deleted.
- If `runGUI` returns nil (only possible with a test fake), `runErr` returns 0 without
  saving again (the callback already did).

Tests in `cmd/fastread/resume_gui_test.go` (fake `runGUI` that calls `finish`
synchronously, then returns nil; fake `exitProcess` records codes and returns; getenv with
`XDG_STATE_HOME=<tmp>/state`, `HOME=<tmp>/home`; seams restored with `t.Cleanup`), named
`TestRunGUIFinishSaves`, table-driven:
- file `book.txt` (`w00`…`w19`), fake calls `finish(4, nil)` → exit codes `[0]`, stderr empty,
  entry index 4 (read via `state.NewStore(<tmp>/state/fastread)` and `Load` with the file's
  `sha256.Sum256`), 0600;
- the next run's fake records `p.Index()` on entry → 4 (resumed), `--start 2` → 2,
  `--no-resume` → 0;
- fake plays to end (`p.Start()`, `for !p.Tick() { time.Sleep(time.Until(p.Deadline())) }`,
  `--wpm 1500 --start 17`) then `finish(p.Index(), nil)` → codes `[0]`, entry deleted;
- `finish(3, errors.New("window lost"))` → codes `[1]`, one stderr line containing
  `window lost`, entry index 3 saved;
- negative: XDG_STATE_HOME below a regular file, `--no-resume`, `finish(1, nil)` → codes
  `[1]`, one line containing `saving reading position`;
- negative: fake calls `finish` twice → `exitProcess` still called once;
- raw `"a b c"` and stdin `"a b c"` with `finish(1, nil)` → codes `[0]`, neither
  `<tmp>/state` nor `<tmp>/home` exists;
- negative: fake returns `gui.ErrNoDisplay` synchronously without calling `finish` → exit
  1, one line, `exitProcess` never called, no entry created.

All existing `cmd/fastread` tests (including `TestRunGUINoDisplay`) keep passing unchanged.

Constraints: change only `cmd/fastread/run.go` and create
`cmd/fastread/resume_gui_test.go`; no new dependency; tests never open a window, `/dev/tty`
or the real state dir; must pass with `-tags nogui` and `CGO_ENABLED=0` (the stub `gui.Run`
has the same signature).

## Verification
`scripts/verify/T035.sh` exits 0. It runs the check command, `TestRunGUIFinishSaves` and the
earlier resume tests (also `-tags nogui`, `-race`), checks the seam and the `sync.Once`
guard, then runs the binary under Xvfb: `--ui gui` on a file, SIGTERM after 3 s → exit 0
and a 0600 entry with index ≥ 1; a restarted run saves again. Negative checks: no display
with a file → exit 1, one line, no state created; raw text under Xvfb creates no state.
