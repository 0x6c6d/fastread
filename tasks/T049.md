# T049: SIGWINCH re-layout and the real /dev/tty (TestLoopResize)

Phase 5 · Model: opus: signal registration and release, real terminal device behaviour and re-layout during playback (R17, Risk "/dev/tty dependence") · Depends-on: T048

## Brief
Package `internal/tui` (module `github.com/0x6c6d/fastread`). Existing (keep names and
behaviour): `Terminal` interface (`Read Write Size MakeRaw Restore Close`), `OpenTTY()
(Terminal, error)` with an unexported real implementation on `/dev/tty` (descriptor via
`SyscallConn().Control`, never `.Fd()`; `golang.org/x/term` raw mode and size), `Run` in
`loop.go` with its redraw (re-queries `t.Size()`, re-splits via `EffectiveSize`/`Split` and
`p.SetParts`, renders), seams `renderFn`, `encodeFn`, `frameHook func(m Model, f Frame)`,
and the fake `Terminal` in the test files.

Add:
1. In `terminal.go`:
   ```go
   // Resizer is implemented by terminals that report size changes. The channel receives
   // (coalesced, never blocking the sender) after each change; Run redraws on it.
   type Resizer interface{ Resized() <-chan struct{} }
   ```
   Split the real implementation's construction into `newTTY(f *os.File) (*<real type>, error)`
   (OpenTTY = open `/dev/tty` O_RDWR + `newTTY`). The real terminal implements `Resizer`:
   `signal.Notify(ch, syscall.SIGWINCH)` with `ch` buffered (cap 1) at construction;
   `Close` calls `signal.Stop(ch)` and is idempotent (second call returns nil or the
   already-closed error, never panics); `Restore` is idempotent.
2. In `loop.go`: if `t` implements `Resizer`, its channel is one more `select` case →
   redraw (new size, new split, `SetParts` keeps the step's elapsed time, focus at the new
   w/2). Without `Resizer` behaviour is unchanged. Size ≤ 0 or below 20×5 must render the
   too-small frame, never panic. A `Size` error after a resize ends Run with an error
   (cleanup as always).

Tests:
- `internal/tui/resize_test.go`, `TestLoopResize` (AC14, R17): a fake terminal that also
  implements `Resizer` (mutex-guarded size; the test sets a size, then signals). Tokens
  `wonderful`, `wonderful`, `wonderful`, `W := strings.Repeat("abcdefghij", 6)`, `end`;
  50 wpm; size 3; start paused (`" "`). Waiting for the frame after each change: 80×24 →
  `f.Size == 3`, measured focus column (min x of `StyleFocus` cells + `glyph.Width(f.Size)/2`)
  is 40; 40×8 → `f.Size == 2`, column 20; 19×4 → `f.Size == 0` and the frame's text is
  only `terminal too small`; 80×24 → `f.Size == 3`, column 40. Then jump to `W` (three
  `"\x1b[C"`): at 80×24 and after resizing to 20×24 `f.Parts` equals `len(Split(W,
  EffectiveSize(W, 3, w, h), w))` and in every hooked frame `m.Part < f.Parts` and
  `p.Parts() == f.Parts`. A burst of 200 resize signals with sizes drawn from w −1..120,
  h −1..40 (deterministic `math/rand/v2`) → no panic, every frame passes the same
  invariants (too-small frames: `f.Size == 0`), Run still running; then `q` → (3, nil) and
  output ends with `RestoreSeq`. Negative row: `Size` returns an error after a resize →
  Run returns a non-nil error, output ends with `RestoreSeq`, Restore and Close called.
- `internal/tui/terminal_test.go`, `TestTTYPty`: open a pty pair with
  `golang.org/x/sys/unix` (`/dev/ptmx` with `O_RDWR|O_NOCTTY|O_CLOEXEC`, unlock with
  `TIOCSPTLCK` 0, number via `TIOCGPTN`, open `/dev/pts/<n>` with `O_NOCTTY`) and wrap the
  slave with `newTTY` (never opens `/dev/tty`; fail, not skip, if no pty can be opened).
  Check: `TIOCSWINSZ` 80×24 on the master → `Size()` = (80, 24); `MakeRaw` → slave termios
  (`TCGETS`) has ICANON and ECHO off; `Restore` → both on again, and a second `Restore` is
  fine; `Write("hi")` is readable from the master; a byte `q` written to the master is
  returned by `Read`; a `Read` blocked on the slave returns an error within 1 s after
  `Close`; `Resized()` receives within 1 s after `syscall.Kill(os.Getpid(),
  syscall.SIGWINCH)`; after `Close` a further SIGWINCH neither blocks nor panics; `Close`
  twice does not panic. Close the master in `t.Cleanup`.

Constraints: change only `internal/tui/terminal.go` and `internal/tui/loop.go`, create the
two test files (extend the fake in an existing test file only by adding code); no new
dependency (`x/sys` and `x/term` are already pinned); all earlier `internal/tui` and
`cmd/fastread` tests keep passing; no `.Fd()`, no `os.Exit`, no Gio.
