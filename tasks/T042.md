# T042: Progress and help rows

Phase 4 · Model: sonnet: two fixed-format text rows with exact expected strings (R27, R28) · Depends-on: T039

## Brief
Package `internal/tui` (module `github.com/0x6c6d/fastread`). Existing (keep):
```go
type Cell struct { Text string; Style Style; Cont bool } // Text "" = blank cell
type Frame struct { W, H int; Cells [][]Cell; Size int } // (more fields may exist; keep them)
type Model struct { Word string; Size int; Paused, ShowProgress, ShowHelp bool
    Index, Total, WPM, EffectiveWPM int } // Index 0-based; EffectiveWPM 0 = unknown
func Render(m Model, w, h int) Frame
func Encode(f Frame, mode ColorMode) []byte // ColorNone, Color16, Color256, ColorTrue
```
Layout today: `Frame.Size` = level drawn (0 = too small, then only `terminal too small`);
the word and its two guide ticks live in rows 1..h−2; row 0 and row h−1 are reserved and
currently empty. The focus column is w/2.

Add to `render.go` (only when `Frame.Size >= 1`; never on the too-small screen):
1. R28 help row: `const HelpText = "space pause  ↑↓ wpm  [ ] size  ←→ word  home restart  p progress  ? help  q quit"`
   (80 runes, each one cell). With `ShowHelp`, row 0 shows it from column 0, clipped at
   the right edge, `StylePlain`; without, row 0 stays blank.
2. R27 progress row h−1 with `ShowProgress`: `text := fmt.Sprintf("word %d/%d  %s wpm",
   m.Index+1, m.Total, e)` with `e = strconv.Itoa(m.EffectiveWPM)` if it is > 0, else `—`
   (U+2014). Let `tw` = rune count of text (each rune one cell). If `w >= tw+2`: bar width
   `bw := w - tw - 1`; `filled := (m.Index+1)*bw/m.Total` clamped to [0, bw] (0 when
   `Total <= 0`); columns [0, filled) are `━` (U+2501), [filled, bw) `─` (U+2500), column bw
   blank, the text from column bw+1 to w−1. Otherwise the text from column 0, clipped. All
   `StylePlain`. Without `ShowProgress` row h−1 stays blank.
3. Neither row changes anything in rows 1..h−2 (R27/R28: toggles never move the focus).

Expected rows (use them literally in the tests): 80×24, `Index 4, Total 120,
EffectiveWPM 287` → row 23 = 2×`━` + 58×`─` + ` ` + `word 5/120  287 wpm`; 80×24,
`Index 0, Total 3, EffectiveWPM 0` → 21×`━` + 43×`─` + ` ` + `word 1/3  — wpm`; 20×5,
`Index 4, Total 120, EffectiveWPM 287` → row 4 = `word 5/120  287 wpm ` (no bar); help at
width 40 → row 0 = the first 40 runes of `HelpText`.

Tests, `internal/tui/rows_test.go`, table-driven:
- `TestProgressHelpFocus` (AC22): words `a`, `Hello`, `wonderful`, `naïve`, `日本` × sizes
  1–5 × frames 80×24, 40×12, 20×5 × the four (`ShowProgress`, `ShowHelp`) combinations:
  rows 1..h−2 are identical cell by cell across the four frames; the measured focus column
  (min x of `StyleFocus` cells, + `glyph.Width(f.Size)/2` when `f.Size >= 2`) is w/2 in
  all; row 0 is `HelpText` clipped (or blank), row h−1 the expected progress row (or
  blank), per the rules and literal rows above.
- `TestNoProgressFrame` (AC22, `--no-progress`): `Model{Word: "Hello", Index: 0, Total: 3,
  ShowProgress: false}` × sizes 1–5 at 80×24: row 23 is blank and `Encode(f, Color16)`
  contains neither `word 1/` nor `wpm`; the same model with `ShowProgress: true` contains
  `word 1/3`. On the too-small screen (19×4) with both toggles on, the frame has neither
  `HelpText` nor `word ` text.
