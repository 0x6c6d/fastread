# T051: E2E stdin, not-found and no-argument TTY (tmux)

Phase 5 · Model: sonnet: e2e tests on the existing tmux harness against existing behaviour (AC1) · Depends-on: T011, T024, T034

## Brief
Package `e2e` (module `github.com/0x6c6d/fastread`; every file starts with `//go:build e2e`
and ends in `_test.go`). Existing helpers in `e2e/helpers_test.go` (use them, do not change
their signatures): `buildBinary(t, buildArgs...) string`, `stateEnv(t) string`
(`XDG_STATE_HOME=<temp dir>`), `newTmux(t, w, h, shellCmd) *tmuxSession` (own `-L` socket,
cleanup kills the server), `capture(escapes bool) string`, `sendKeys(keys...)`,
`resize(w, h)`, `waitFor(cond, timeout) (string, bool)`, `watchWords(words, timeout)
(seen []string, exit int)` (needs a pane line `EXIT:<n>`), and the shell single-quoting
helper. Shell commands follow the pattern `env <stateEnv> <bin> <args>; echo "EXIT:$?";
sleep 600`.

Binary behaviour under test (R1, R7, A3, Plan row 24): with no argument and stdin not a TTY,
stdin is read as UTF-8 (invalid bytes → U+FFFD), keys still come from `/dev/tty`; raw
text and stdin never create resume state; an argument that is not an existing file and looks
like a path (no whitespace and contains `/`, starts with `.` or `~`, or ends in `.txt .md
.epub .fb2 .pdf`) → exactly one stderr line `fastread: … not found …`, exit 1, nothing on
stdout; a non-path-like word (`nope`) is raw text; no argument with stdin a TTY → error line
plus usage (`Usage: fastread`) on stderr, exit 2.

Create `e2e/cli_test.go`:
- `TestE2EStdin` (80×24, own tmux each subtest, `--size 1`):
  - `utf8`: `printf 'alpha \377beta\n\ngamma' | <bin> --no-resume --size 1 --wpm 120` →
    `watchWords` sees `alpha`, `�beta`, `gamma` in order, exit 0.
  - `keys`: stdin of 200 words `s000`…`s199` piped, `--wpm 60`: once `s001` is on screen
    send `q` → exit 0 within 2 s (keys work although stdin is a pipe).
  - after both: the `XDG_STATE_HOME` directory of each run is still empty.
- `TestE2ENotFound`: run the binary with `exec.CommandContext` (10 s timeout, `Dir` a temp
  dir, `stateEnv` in `Env`, stdin `/dev/null`) for `./nope.txt`, `nope.epub`,
  `sub/missing.md`, `/nonexistent-fastread-dir/x.pdf`: exit code 1, stdout empty, stderr
  exactly one line, starting `fastread: ` and containing `not found`. Contrast row in tmux:
  `<bin> --no-resume --size 1 --wpm 1500 nope` → `watchWords` sees `nope`, exit 0.
- `TestE2ENoArgTTY`: in tmux (stdin is the pane's TTY): `<bin>` with no argument and
  `2>err` redirected to a temp file → pane shows `EXIT:2` within 5 s; the err file's first
  line starts with `fastread: ` and the file contains `Usage: fastread`; nothing was played
  (no alternate screen: the pane never shows a progress row `word 1/`).
On failure log the last captured screen and stderr.

Constraints: create only `e2e/cli_test.go`; never use the default tmux server, the user's
sessions or the real `~/.local/state`; every external call under a timeout; no fixed sleeps
longer than the 20 ms poll; whole file runs well under 120 s; `go vet -tags e2e ./...` clean.

## Verification
`scripts/verify/T051.sh` exits 0. It runs the check command, `go vet -tags e2e`, and
`TestE2EStdin`, `TestE2ENotFound`, `TestE2ENoArgTTY` plus `TestE2EBasic` with `--- PASS`
lines, then checks that no `fastread-e2e-*` tmux server and no `fastread` process is left and
the real `~/.local/state/fastread` was not created.
