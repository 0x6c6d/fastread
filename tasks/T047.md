# T047: Key decoder with escape sequences (TestKeyDecode)

Phase 5 · Model: sonnet: pure byte-level state machine with a complete table and a fuzz property; no I/O or goroutines · Depends-on: T007

## Brief
Create `internal/tui/keys.go` in package `internal/tui` (module `github.com/0x6c6d/fastread`):
the decoder that turns raw bytes read from the terminal (raw mode) into R26 actions. It is
pure: no I/O, no goroutines, no clock (the loop owns the Esc timeout). Actions come from
`internal/state`: `ActTogglePause ActWPMUp ActWPMDown ActSizeDown ActSizeUp ActPrev ActNext
ActHome ActToggleProgress ActToggleHelp ActQuit` (type `state.Action`).

```go
// EscTimeout is how long a lone ESC waits for the rest of an escape sequence; the loop calls
// Flush when no byte arrived within it.
const EscTimeout = 50 * time.Millisecond
// KeyDecoder turns raw terminal bytes into actions. The zero value is ready to use; it is
// not safe for concurrent use.
type KeyDecoder struct{ /* unexported */ }
// Feed decodes b after any bytes kept from earlier calls and returns the complete actions in
// input order. An unfinished escape sequence at the end is kept for the next call.
func (d *KeyDecoder) Feed(b []byte) []state.Action
// Pending reports whether an unfinished escape sequence (or a lone ESC) is buffered.
func (d *KeyDecoder) Pending() bool
// Flush ends a pending sequence: a lone ESC yields ActQuit (the Esc key); an unfinished
// longer sequence is dropped. Afterwards Pending is false.
func (d *KeyDecoder) Flush() []state.Action
```
Mapping:
- Single bytes: `' '` → TogglePause; `q` → Quit; `0x03` (Ctrl+C) → Quit; `[` → SizeDown;
  `]` → SizeUp; `p` → ToggleProgress; `?` → ToggleHelp. Every other byte outside a sequence
  (letters incl. `Q`, digits, other controls, DEL, UTF-8 bytes) is ignored.
- `ESC [` (CSI) or `ESC O` (SS3) start a sequence. CSI = `ESC [`, parameter bytes
  0x30–0x3F, intermediate bytes 0x20–0x2F, one final byte 0x40–0x7E. SS3 = `ESC O` + one
  byte 0x40–0x7E. Mapped: `ESC[A`/`ESCOA` → WPMUp; `B` → WPMDown; `C` → Next; `D` → Prev;
  `ESC[H`, `ESCOH`, `ESC[1~`, `ESC[7~` → Home. Every other complete sequence (e.g. `ESC[5~`,
  `ESC[1;5C`, `ESCOP`, `ESC[200~`) is consumed and ignored — its bytes are never decoded as
  single keys (`[` inside `ESC[` is not SizeDown; `ESC` inside a sequence is not Esc).
- A byte that is invalid at its position inside a sequence ends the sequence silently and is
  then decoded as a normal byte.
- `ESC` followed by `ESC` → the first is the Esc key (Quit), the second starts anew.
  `ESC` followed by any byte other than `[`, `O`, `ESC` → Quit, then that byte is decoded
  normally.
- `0x03` always means Quit immediately, also inside a pending sequence (which is dropped).
- At most 32 bytes are buffered: a sequence longer than that is dropped and the decoder
  skips input up to and including the next byte in 0x40–0x7E.
- Bytes of one key may arrive in any number of `Feed` calls with the same result.

Tests, `internal/tui/keys_test.go`, table-driven:
- `TestKeyDecode`: rows of (chunks []string, want actions, want Pending after): every single
  key above; `"\x1b[A" "\x1b[B" "\x1b[C" "\x1b[D" "\x1bOA" "\x1bOB" "\x1bOC" "\x1bOD"
  "\x1b[H" "\x1bOH" "\x1b[1~" "\x1b[7~"`; ignored sequences `"\x1b[5~" "\x1b[1;5C" "\x1bOP"
  "\x1b[200~"` → none; `"\x1b"` → none, Pending, then `Flush()` → [Quit]; `"\x1b\x1b[C"` →
  [Quit, Next]; `"\x1bx"` → [Quit]; `"\x1bp"` → [Quit, ToggleProgress]; `"\x1b[\x03"` →
  [Quit]; `"[]p?"` → [SizeDown, SizeUp, ToggleProgress, ToggleHelp]; `"Qx9\x7f\xc3\xa9"` →
  none; `"\x1b[" + 40×"1" + "~ "` → [TogglePause] and Pending false; `"\x1b[" + "1" ×
  100 000` → none, buffer never above 32 bytes. For every mapped sequence and every split
  point i, `Feed(s[:i])` then `Feed(s[i:])` gives the same actions; byte-by-byte feeding too.
  `Flush` without anything pending returns nothing.
- `FuzzKeyDecode(f *testing.F)` (seeds: the rows above): feeding the input whole and byte
  by byte never panics, gives the same actions both ways, every action is a valid R26
  action, the buffer never exceeds 32 bytes, and after `Flush` `Pending()` is false.

Constraints: create only `internal/tui/keys.go` and `internal/tui/keys_test.go`; do not wire
the decoder into `Run` (a later task does); no I/O, no `os`, no goroutines, no sleeps;
earlier `internal/tui` tests keep passing.
