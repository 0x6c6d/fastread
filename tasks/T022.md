# T022: PDF hostile-input suite (corrupt, panicking, looping files)

Phase 2 · Model: opus: negative-test scrutiny of the PDF call site against panics and endless loops (R6, §5 security; Consequential assumption 16; Risk "untrusted parsing") · Depends-on: T021

## Brief
Prove, and where needed fix, that the PDF loader in package `internal/input` (module
`github.com/0x6c6d/fastread`) turns every malformed PDF into a typed error quickly, never a
panic or a hang. Existing (do not change their signatures): `loadPDF(b []byte, lim Limits)
([]string, error)` in `pdf.go` (all `github.com/ledongthuc/pdf` calls inside one
`recoverAs(ErrCorruptPDF, …)`; own page-tree walk with depth ≤ 32, ≤ 100000 visited nodes,
`MaxPDFPages = 10000`; per-page `GetPlainText(nil)`; `ErrNoText` when no text);
`buildPDF(pages []string) []byte` in `pdf_fixture_test.go` (minimal deterministic PDF 1.4 with
xref table); sentinels `ErrCorruptPDF`, `ErrNoText`, `ErrTooLarge`, `ErrUnsupported`;
`DefaultLimits()`; `LoadFile(path string) (Document, error)`.

Create `internal/input/pdf_corrupt_test.go` with table-driven `TestPDFCorrupt`. Each row
builds its bytes (from `buildPDF` output with byte surgery, or by hand-writing a small PDF
with a recomputed xref; add a helper `rawPDF(objects []string) []byte` that numbers objects
from 1 and writes a correct xref/trailer with `/Root 1 0 R`), runs `loadPDF(b,
DefaultLimits())` in a goroutine and fails the row if it does not return within 2 s (20 s
when built with `-race`; use the package's `raceEnabled` test constant if it exists, else
add `//go:build race` / `!race` constant files declaring it). Expected results:
- `ErrCorruptPDF` (and not `ErrNoText`): `%PDF-1.4\n` alone; header + 1 KiB of random bytes
  (fixed seed); the sample truncated at 25 %, 50 %, 90 % and with its last 30 bytes removed;
  `startxref` pointing past the end; an xref table whose offsets all point to byte 0; a
  Pages node whose `Kids` contains itself (`2 0 R` inside object 2); Pages nested 40 deep;
  a content stream with a `Tj` that has no operand, and one with a `Tf` with one operand
  (the library panics "bad Tj operator"/"bad TL"); a `/Root` that is not a dictionary, and a
  catalog without `/Pages` (rule to add in `pdf.go` if missing: the root Pages node must be a
  dictionary with `/Type /Pages`, else `ErrCorruptPDF`).
- `ErrNoText` (and not `ErrCorruptPDF`): `/Count 2000000000` with an empty `Kids` array
  (must still return within the time bound: the walk ignores `/Count`); a valid page without
  a `Contents` key.
- `ErrCorruptPDF` or `ErrNoText` (assert one of the two plus the time bound; comment which
  one occurs): a Page whose `Contents` references an object number missing from the xref.
- `ErrUnsupported`: a trailer with an `/Encrypt` dictionary whose user password is not empty
  (any `/Filter /Standard /V 1 /R 2` dict with garbage `/O`/`/U` strings is enough; if the
  library instead reports another error, the loader must still return `ErrUnsupported` or
  `ErrCorruptPDF` – assert one of the two and record which in a comment).
- `ErrTooLarge`: the sample with `Limits{MaxBytes: 100, MaxEntries: 1, MaxDepth: 1}`.
- loads fine: a Pages tree two levels deep (Pages → Pages → 3 Page objects) yields the
  three page texts in order.
Every error message is one line (no `\n`). The test also asserts
`runtime.NumGoroutine()` is back to its start value (poll up to 1 s) after all rows, so no
row leaves a goroutine spinning.

If a row fails, fix `pdf.go` only (stricter checks before calling into the library, more
validation in the page-tree walk); never modify the library or vendor it. If a library hang
cannot be prevented from outside, stop and report the exact input instead of weakening a row.

Constraints: no new dependency; change only `pdf.go`, `pdf_corrupt_test.go` and, if needed,
the race constant files.

## Verification
`scripts/verify/T022.sh` exits 0. It runs the check command, `TestPDFCorrupt` (normal and
`-race`, with an outer timeout) and the earlier PDF tests. Negative checks: hostile PDFs
written by the script (truncated, self-referencing `Kids`, operator-less `Tj`) make the binary
exit 1 within 5 s with one stderr line and no `panic`/`goroutine` text.
