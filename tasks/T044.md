# T044: Golden frames for sizes 1-5, ticks, toggles and fallbacks

Phase 4 · Model: sonnet: test-only golden harness over an already-specified renderer (R15, R19, R27, R28, R33) · Depends-on: T041, T042, T043

## Brief
Package `internal/tui` (module `github.com/0x6c6d/fastread`). Existing (do not change
non-test code; if a golden looks wrong, report it with the frame instead of editing code):
```go
type Style uint8 // StylePlain, StyleFocus, StyleTick
type Cell struct { Text string; Style Style; Cont bool } // Text "" = blank
type Frame struct { W, H int; Cells [][]Cell; Size, Parts int } // Size 0 = too small
type Model struct { Word string; Size int; Paused, ShowProgress, ShowHelp bool
    Index, Total, WPM, EffectiveWPM, Part int }
func Render(m Model, w, h int) Frame
```
Known behaviour: focus on column w/2; sizes 2–5 are block glyphs 3/5/7/9 rows high (the
whole focus glyph box is `StyleFocus`), ticks `│` (`StyleTick`) directly above and below
the word rows, help on row 0, progress on row h−1, long words split into `Parts` steps.

Create `internal/tui/golden_test.go` and the golden files:
1. `var update = flag.Bool("update", false, "rewrite golden files")`. `TestGolden` renders
   each case, serialises it and compares with `internal/tui/testdata/golden/<name>.golden`
   byte for byte; on mismatch it fails naming the first differing line. A missing file is
   a failure unless `-update` is given; only `-update` writes files
   (`go test ./internal/tui -run '^TestGolden$' -update`).
2. Format (Plan row 35): line 1 `# <name> w=<W> h=<H> size=<Frame.Size> parts=<Frame.Parts>`;
   then H text lines: each cell's Text (blank → one space, `Cont` → nothing) followed by
   `|` (keeps trailing blanks visible); then a line `--`; then H mask lines of exactly W
   characters: `F` for `StyleFocus`, `T` for `StyleTick`, `.` otherwise; final newline.
3. Cases, 80×24 unless noted; base model `Model{ShowProgress: true, Index: 4, Total: 120,
   WPM: 300, EffectiveWPM: 287}`:
   - `<word>_s<n>` for words `a`, `Hello`, `wonderful`, `naïve` (file stem `a`, `hello`,
     `wonderful`, `naive`) × n = 1..5 (20 files);
   - `hello_s3_paused` (`Paused: true`), `hello_s2_progress_off`, `hello_s2_help_on`,
     `naive_s1_help_on_progress_off`, `wonderful_s5_part1` (`Part: 1`),
     `nihon_s3_fallback` (`日本`, size 3), `hello_s5_40x8` (40×8), `toosmall_19x4` (19×4).
4. Assertions besides equality (computed from the frame, not the file): for the 20 word
   cases the number of rows holding a `StyleFocus` cell is 1, 3, 5, 7, 9 for sizes 1–5
   (AC12); in every case with `Size >= 1` there is a `StyleTick` cell at column 40 directly
   above the first and directly below the last focus row (AC16, also `hello_s3_paused`);
   the toggle cases have the same focus column and word rows as `hello_s2` / `naive_s1`
   (AC22). Expected headers (pinned by the geometry): `wonderful_s3` parts=1,
   `wonderful_s4` and `wonderful_s5` parts=2, `nihon_s3_fallback` size=1,
   `hello_s5_40x8` size=2, `toosmall_19x4` size=0 parts=0.

Generate the files with `-update`, inspect a few (`cat internal/tui/testdata/golden/hello_s3.golden`)
and make sure they show the documented layout, then run without `-update`.

Constraints: create only `internal/tui/golden_test.go` and
`internal/tui/testdata/golden/*.golden`; stdlib `testing`, `flag`, `os`, `strings` only.
