# T064: E2E GUI error paths and the nogui binary

Phase 6 · Model: sonnet: three e2e tests over existing binaries and helpers; the error handling itself is opus-built and verified (R24, R31, AC20, AC25) · Depends-on: T011, T062

## Brief
Package `e2e` (module `github.com/0x6c6d/fastread`; every file starts with `//go:build
e2e`, `_test.go` suffix). Existing helpers in `e2e/helpers_test.go` (do not change
signatures): `buildBinary(t, buildArgs...) string` (runs `go build <buildArgs> -o …
./cmd/fastread` from the module root, cached), `stateEnv(t)`, `newTmux(t, w, h,
shellCmd)`, `watchWords(words, timeout) (seen []string, exit int)`, `capture`, the shell
single-quoting helper (read the file for its name).

Behaviour under test:
- R24/AC20: with neither `DISPLAY` nor `WAYLAND_DISPLAY`, `fastread --ui gui <text|file>`
  prints exactly one line `fastread: …` to stderr (nothing on stdout), exits 1 at once and
  creates no state. With a display that cannot be opened (Gio reports it through
  `DestroyEvent.Err`, e.g. `wayland: wl_display_connect failed: …`) it prints exactly one
  `fastread: ` line and exits 1 within a second, never a panic or stack trace.
- R31/AC25: `CGO_ENABLED=0 go build -tags nogui ./cmd/fastread` gives a binary without any
  `gioui.org` code (`go version -m` and `go tool nm` show none); its `--ui gui` prints one
  line containing `GUI not available` and exits 1 whatever `DISPLAY` is; its TUI works.

Create `e2e/guierr_test.go` (every external command under a context timeout; envs built
from `os.Environ()` with `DISPLAY`, `WAYLAND_DISPLAY`, `XDG_STATE_HOME`,
`XDG_RUNTIME_DIR` removed, then the listed variables added; never the user's display):
- helper `freeDisplay(t) string`: the first `:N`, N in 900–999, with neither
  `/tmp/.X11-unix/X<N>` nor `/tmp/.X<N>-lock`.
- `TestE2EGUINoDisplay`: subtests `raw` (`--ui gui x`) and `file` (a temp `b.txt`):
  exit 1 within 5 s, stderr exactly one line starting `fastread: `, stdout empty, the
  temp `XDG_STATE_HOME` directory not created.
- `TestE2EGUIBadDisplay`: subtests `x11` (`DISPLAY=` freeDisplay) and `wayland` (no
  `DISPLAY`, `WAYLAND_DISPLAY=fastread-e2e-none-<pid>`), both with `XDG_RUNTIME_DIR` = a
  new 0700 temp dir: `--ui gui "hello world"` exits 1 within 10 s, stderr exactly one
  line starting `fastread: `, containing neither `panic` nor `goroutine `.
- `TestE2ENoguiBinary`: build itself (`go build -tags nogui -o <tmp>/fastread
  ./cmd/fastread` from the module root with `CGO_ENABLED=0`, 300 s timeout); `go version -m
  <bin>` and `go tool nm <bin>` outputs contain no `gioui.org`; `--ui gui x` with no display
  and with `DISPLAY=` freeDisplay → exit 1, exactly one stderr line containing `GUI not
  available`; in an own tmux 80×24 (`newTmux`), `<bin> --no-resume --size 1 --wpm 120 'a b
  c'` → `watchWords` sees `a`, `b`, `c` and exit 0 within 20 s.

Constraints: create only `e2e/guierr_test.go`; stdlib only; no process left running; never
the real `~/.local/state` or the user's tmux/X; whole file well under 120 s (the nogui build
excepted); `go vet -tags e2e ./...` clean.
