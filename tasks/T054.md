# T054: E2E live resize (TestE2EResize)

Phase 5 · Model: sonnet: e2e test on the existing tmux harness and screen parser (AC14 live part) · Depends-on: T049, T053

## Brief
Package `e2e` (module `github.com/0x6c6d/fastread`; every file starts with `//go:build e2e`,
`_test.go` suffix). Existing helpers (do not change signatures): in `e2e/helpers_test.go`
`buildBinary`, `stateEnv`, `newTmux(t, w, h, shellCmd)`, `capture(escapes bool)`,
`sendKeys(keys...)`, `resize(w, h)` (tmux `resize-window`), `waitFor(cond, timeout)`,
`watchWords`, the shell single-quoting helper; in `e2e/screen_test.go`
`parseScreen(capture(true)) [][]cell` (`cell{Text, Col, Focus, Reverse, Colored}`),
`focusCols`, `tickCols`; in `e2e/proc_test.go` `paneState()`, `appPID()`. Import
`github.com/0x6c6d/fastread/internal/tui/glyph` for `glyph.Width(size)`, `glyph.Rows(size)`.

Behaviour under test (R17, AC14, Plan row 27): on SIGWINCH the TUI re-lays out at once,
the focus stays at the new w/2; the size falls back to the largest level whose rows fit
(`glyph.Rows(s) ≤ h − 4`, plus a width condition for sizes ≥ 2); below 20×5 the screen shows
only `terminal too small` (row h/2) and nothing else; the program keeps running. Level s
draws `glyph.Rows(s)` word rows between the two ticks `│` in column w/2. Paused (`Space`)
the word does not change.

Create `e2e/resize_test.go`, `TestE2EResize`: tmux 80×24, `env TERM=tmux-256color
COLORTERM=truecolor <stateEnv> <bin> --no-resume --size 3 --wpm 60 '<wonderful × 40>';
echo "EXIT:$?"; sleep 600`. Wait for the first frame, send `Space` (pause). A screen is
accepted only when two consecutive captures are identical. Then, in order:
1. 80×24: exactly two ticks, both column 40, their rows differ by `glyph.Rows(3)+1` (the
   word rows lie strictly between them); non-space focus cells inside [40 − W/2,
   40 − W/2 + W), W = `glyph.Width(3)`.
2. `resize(40, 8)`: within 2 s two ticks at column 20 whose rows differ by
   `glyph.Rows(2)+1`; focus cells inside the `glyph.Width(2)` box around column 20.
3. `resize(19, 4)`: within 2 s the screen trimmed of blank space is exactly
   `terminal too small`, no tick, no focus cell.
4. `resize(1, 1)` and `resize(10, 3)`: the process is still alive (no `EXIT:` line after
   1 s; `appPID` still exists).
5. `resize(80, 24)`: within 2 s the state of step 1 again.
6. `resize(121, 30)`: ticks at column 60, size 3.
7. `q` → `EXIT:0` within 2 s.
Log the screen of the failing step.

Constraints: create only `e2e/resize_test.go`; never use the default tmux server, the
user's sessions or the real `~/.local/state`; every external call under a timeout; whole
test well under 120 s; `go vet -tags e2e ./...` clean.
