# T062: GUI exit path and display errors (finish exactly once, R24)

Phase 6 · Model: opus: the `app.Main`/`finish` exit path and display-error handling decide the exit code and whether the position is saved (Risk "GUI exit path", Consequential assumption 8, R24, Plan row 6) · Depends-on: T061

## Brief
Package `internal/gui` (module `github.com/0x6c6d/fastread`). Existing (keep names and
behaviour): `gui.go` (`Options{Getenv}`, `ErrUnavailable`, `ErrNoDisplay`, display-env
helper), `stub.go` (`nogui || !cgo`), `window.go` (`!nogui && cgo`): `Run(ctx, p, opts,
finish func(last int, err error)) error`, the window goroutine (keys via
`keyFilters`/`keyAction`, `Layout`/`LayoutChrome` drawing, Player deadlines via
`op.InvalidateCmd`), the ctx helper goroutine (`ctx.Done()` → `w.Invalidate()`), then
`app.Main()`. cmd's `finish` saves or deletes the resume entry, prints at most one line
`fastread: <msg>` and calls `os.Exit` (Gio's `app.Main` never returns on Linux).

Make the exit path one explicit, display-free, tested unit:
1. New `internal/gui/session.go`, NO build tag, NO `gioui.org` import:
   ```go
   // session ends a GUI run exactly once: finish(p.Index(), err) is called by the first
   // end; later calls (from any goroutine) do nothing.
   type session struct{ /* p, finish, sync.Once, done flag */ }
   func newSession(p *state.Player, finish func(last int, err error)) *session
   func (s *session) end(err error)
   func (s *session) ended() bool
   // guard is deferred at the top of the window goroutine: a panic becomes
   // end(fmt.Errorf("gui: internal error: %v", r)); it never re-panics.
   func (s *session) guard()
   // windowErr maps app.DestroyEvent.Err: nil → nil (close button = quit, R26/Plan row
   // 31); else fmt.Errorf("gui: window: %w", err), newlines replaced by spaces.
   func windowErr(err error) error
   ```
   `finish` itself panicking inside `end` must not escape `guard`, and `end` is still
   "done" afterwards. `ended()` is safe to call concurrently.
2. `window.go` uses only the session on every path: quit key (`q`, Esc, Ctrl+C via
   `keyAction` → `ActQuit`) → `end(nil)`; `app.DestroyEvent` → `end(windowErr(e.Err))`;
   `p.Tick()` finished → `end(nil)`; ctx done (SIGINT/SIGTERM in cmd) → `end(nil)`;
   `defer s.guard()`. After `end` the window goroutine stops handling events and returns
   (in tests `finish` returns instead of exiting); the ctx helper goroutine also ends
   (it selects on ctx and on a `done` channel closed at the end).
3. R24: a display that cannot be opened (bad `DISPLAY`, unusable `WAYLAND_DISPLAY`; Gio
   reports it as `DestroyEvent.Err`, e.g. `wayland: wl_display_connect failed: …`) ends
   with one line `fastread: gui: window: …` and exit 1 within a second, never a panic or
   a stack trace; no `DISPLAY` and no `WAYLAND_DISPLAY` stays the synchronous
   `ErrNoDisplay` path (finish never called). The nogui/no-cgo stub is unchanged.

Tests `internal/gui/session_test.go` (no build tag; runs in all builds; fake `finish`
records calls; table-driven): `TestGUIExitPath`: `end(nil)` → one call `(p.Index(),
nil)`; `end(nil)` after `Apply(ActNext)` passes the new index; `end(errA)` then `end(nil)`
→ one call with errA; 50 goroutines calling `end` concurrently → exactly one call (`-race`
clean); `defer guard()` around `panic("boom")` → one call whose error is `gui: internal
error: boom`, single line, nothing escapes; panic after `end` → still one call; `finish`
that panics → `guard` contains it, `ended()` true; `windowErr(nil) == nil`;
`windowErr(e)` matches `errors.Is(…, e)`, starts with `gui: window: `, has no newline for
an error text containing `\n`.

Constraints: create `session.go`, `session_test.go`; change `window.go` only as needed;
no `os.Exit` in `internal/gui`; tests open no window; all earlier `internal/gui` and
`cmd/fastread` tests keep passing (also `-tags nogui`, `CGO_ENABLED=0`).

## Verification

`-race -count=3`, `nogui`, no cgo) and the earlier GUI/cmd tests, then on an own Xvfb:

no state created; `session.go` has no Gio import and no build tag; no `os.Exit`.
