# T055: E2E resume and SIGTERM state save

Phase 5 · Model: sonnet: e2e tests over the already opus-built and verified resume wiring, on the existing harness (AC23, AC26 live parts) · Depends-on: T034, T052

## Brief
Package `e2e` (module `github.com/0x6c6d/fastread`; every file starts with `//go:build e2e`,
`_test.go` suffix). Existing helpers (do not change signatures): in `e2e/helpers_test.go`
`buildBinary`, `stateEnv(t)` (`XDG_STATE_HOME=<temp dir>`), `newTmux(t, w, h, shellCmd)`,
`capture`, `sendKeys`, `waitFor`, `watchWords`, the shell single-quoting helper; in
`e2e/proc_test.go` `paneState() (altScreen, cursorVisible bool)` and `appPID() int`.

Behaviour under test (R29, R32, Plan rows 21-23, 31): for a file source the resume entry is
`$XDG_STATE_HOME/fastread/<hex sha256(abs path)>.json` = `{"path","sha256","index"}`, dir
0700, file 0600, written atomically on `q`/Esc/Ctrl+C and on SIGINT/SIGTERM (exit 0, terminal
restored, < 1 s); index = word on screen; on start the saved index is used unless `--start`
or `--no-resume` is given or the file's content changed (then 0, no warning); reaching the
end deletes the entry; raw text and stdin never create state.

Fixture: `book.txt` in a temp dir with 200 words `w0000`…`w0199` (one line); the path given
to the binary is its absolute, symlink-resolved path. The word on screen = the first
`w[0-9]{4}` match of `capture(false)` (`--size 1`, so the word is plain text). Each run gets
its own tmux session (80×24) but runs within one test share one `XDG_STATE_HOME`. Helper in
the new file: `entry(t, stateDir) (path string, index int)` that requires exactly one
`*.json` in `<stateDir>/fastread` and decodes it.

Create `e2e/resume_test.go`:
- `TestE2ESIGTERMSavesState` (AC26), subtests `SIGTERM` and `SIGINT`: `--size 1 --wpm 50
  book.txt`; once `w0002` is on screen, record the shown word k, `syscall.Kill(appPID(),
  sig)`; `EXIT:0` appears within 1 s of the signal (measure and log the ms); the entry exists,
  mode 0600 in a 0700 directory, `path` equals the book's path, `index` is k or k+1, the
  file contains no `w0` text; `paneState` reports main screen and visible cursor.
- `TestE2EResume` (AC23 live): in order, (1) run, at `w0003` send `q` → exit 0, saved
  index i ≥ 3; (2) rerun → the first word shown is `w%04d` of i; send `Escape` → exit 0;
  (3) `--start 5` → first word `w0005`, `q`; (4) `--no-resume` → `w0000`, `q` at once, saved
  index afterwards ≤ 2; (5) append ` w0200` to the book → rerun shows `w0000` first, stderr
  (redirect `2>` a temp file) has no `warning`, `q`; (6) `--wpm 1500 --start 195` plays to
  the end → exit 0 and `<stateDir>/fastread` has no `*.json` left; (7) raw text
  `'xq1 yq2 zq3'` quit with `q` and stdin `printf 'a b c' |` played to the end with a
  fresh `XDG_STATE_HOME` → that directory stays empty.
Log screens and the entry content on failure.

Constraints: create only `e2e/resume_test.go`; never use the default tmux server, the user's
sessions or the real `~/.local/state`; never signal a PID `appPID` did not verify; every
external call under a timeout; no fixed sleeps longer than the 20 ms poll; whole file well
under 120 s; `go vet -tags e2e ./...` clean.
